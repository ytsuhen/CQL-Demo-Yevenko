    How to read the trace

    Each trace row is one step of the rule (define) and its value for this patient. null means “no value”: the rule never silently turns it into false. A ✓ marks a step the scenario checks.

    Three 10-minute exercises

    EXERCISE 1

    Add a test patient without code

    1. Press “+ Scenario” above the editor.
    2. Look at the fields: the patient’s facts and the expected result expect.
    3. Press “Compile & run”.

    Expected: all passed. This is how a UAT scenario is added: just facts and expectations.

    EXERCISE 2

    Change a threshold and see what it affects

    1. Open HeadacheTriage.cql and find define "Severe Pain".
    2. Change "Pain Now" >= 8 to >= 9.
    3. Run the scenarios.

    Expected: one fails. Scenario h03 (pain 8, nothing else) fails: it now gets Reassure instead of Provider notification. The boundary test caught the change.

    EXERCISE 3

    Make a typo in a name

    1. In the same define "Severe Pain" rename "Pain Now" to "Pain Score".
    2. Run the scenarios.
    3. Click the error: the editor jumps to that line.

    Expected: an error with the file, line and column, plus the steps that depend on it. Click it and the editor jumps to the exact spot.

    After the exercises press “Reset changes” to restore the files. Edits are stored only in your browser.
